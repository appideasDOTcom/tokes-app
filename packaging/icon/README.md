# Tokes app icon — handover

Everything here is generated by `../build_marks.py`, which is the only writer.
Hand-edit anything in this directory and the next build silently reverts you.
The mark and the reasoning behind it are in
`../../../decisions/0011-tokes-mark-is-a-cycle-not-a-chart.md`.

## What to take

**`Tokes.icon/`** — the entire deliverable. One Icon Composer package.

**`masters/`** — the SVG masters, so a future re-cut does not need a round trip
through the design practice.

That is all. **Do not ask for a legacy `.icns`, an `.appiconset`, or rendered PNG
size sets.** `actool` derives every shipping form from the package, and when a
`.icon` is present an appiconset passed under the same `--app-icon` name is
*silently ignored* — cutting one is wasted work that also looks like it is doing
something.

## How it is consumed

Verified end to end on 2026-08-19, not taken from documentation:

```sh
xcrun actool Tokes.icon --compile <out> --app-icon Tokes --include-all-app-icons \
  --output-partial-info-plist <plist> --platform macosx --target-device mac \
  --minimum-deployment-target 14.0
```

Emits, with zero errors or warnings:

- `Assets.car` — the layered Tahoe rendition, full-bleed
- `Tokes.icns` — the legacy rendition, inset to ~83.6% of canvas, containing
  `ic04 ic11 ic07 ic13` = 16, 32, 128, 256 px. Topping out at 256 is correct;
  Apple's own system apps ship exactly this set.
- a partial plist carrying `CFBundleIconFile` and `CFBundleIconName`

**One source, both forms.** macOS 14/15 needs an app-drawn inset tile and macOS
26 needs full-bleed artwork the system masks — genuinely different pixels — but
`actool` does that derivation. We author full-bleed only.

## What must not be baked in

The mask, the drop shadow and the Liquid Glass specular are all applied by the
system. None of them is in the source, and none should be added. The `fill` in
`icon.json` is a flat brand blue; the gradients you see in a rendered icon are
the platform's, not ours.

## Checking a change

```sh
IC="/Applications/Xcode.app/Contents/Applications/Icon Composer.app/Contents/Executables"
"$IC/ictool" Tokes.icon --export-image --output-file out.png --platform macOS \
  --rendition Default --width 16 --height 16 --scale 1
```

`--rendition` takes six values, not two: `Default`, `Dark`, `TintedLight`,
`TintedDark`, `ClearLight`, `ClearDark`. `--tint-color` and `--tint-strength`
work. **All six were rendered and checked on 2026-08-19 and the mark holds in
every one** — see `../review/renditions.png`. That is the gap rule earning its
keep: in the four tinted and clear renditions the accent and the remainder
collapse to a single tint, and only the geometry is left to carry the meaning.

**Every path passed to `actool` must be absolute.** It runs as a persistent XPC
service that can carry a *stale* working directory between invocations, and it
will fail with `The output directory "…" does not exist` naming a path you did
not pass in that command. The arguments are not the problem when that happens.
Found by `tokes-developer`, at the cost of a real debugging cycle.

**The dark-appearance ground is not authorable. Do not go looking for a key.**
It is system-controlled: changing the base `fill` to a vivid red changes the
`Default` rendition and leaves `Dark` byte-identical, so the base fill does not
reach that rendition at all. Verified independently on both sides.

**Judge 16px by eye, not by a script.** A component count run over `ictool`
output is unreliable: the Liquid Glass gradient shades the lower part of the
accent arc dark enough that a luminance threshold splits one arc into two and
reports a break that is not there. Counting is valid against the flat source
SVGs in `masters/`, which is what `../measure_marks.py` uses.

## The one thing that will break this mark

Its meaning is carried by the **gaps**, not by the colour — that is why it
survives the tinted and monochrome renditions, where the accent and the
remainder become one tint and only the geometry is left.

The ring wall is 5.6 units on the 32-unit grid. At 4.8 it fragmented at 16px in
the inset rendition. **Do not thin the wall, and do not close the gaps.** If the
geometry changes at all, re-run `../measure_marks.py` and look at 16px by eye.
